# Fix recipes by ecosystem

The scan's `fixPlan[].command` gives a starting command. Details and the transitive-package options are below. Always use the package manager (not hand-edited lockfiles) so the lockfile stays consistent.

## npm (package-lock.json)
- Direct: `npm install <pkg>@<fixed>` (add `--save-dev` for devDependencies).
- Transitive: `npm update <pkg>` first. If `npm ls <pkg>` still shows the old version (a parent pins it), add an override in `package.json` and reinstall:
  ```json
  "overrides": { "<pkg>": "<fixed>" }
  ```
  Scoped to one parent: `"overrides": { "<parent>": { "<pkg>": "<fixed>" } }`.
- Verify: `npm ls <pkg>` and `npm audit`.

## pnpm (pnpm-lock.yaml)
- Direct: `pnpm add <pkg>@<fixed>` (`-D` for dev). Workspace: `pnpm add <pkg>@<fixed> --filter <project>`.
- Transitive: `pnpm update <pkg> --depth Infinity`; if still old, add to `pnpm-workspace.yaml` (pnpm 10) or `package.json` → `"pnpm": { "overrides": { ... } }` (older):
  ```yaml
  overrides:
    "<pkg>": "<fixed>"
  ```
  then `pnpm install`. Verify with `pnpm why <pkg>`.

## Yarn
- Classic: `yarn upgrade <pkg>@<fixed>`; transitive → `"resolutions": { "<pkg>": "<fixed>" }` in package.json, then `yarn install`.
- Berry: `yarn up <pkg>@<fixed>`; transitive → `yarn up -R <pkg>`, or `resolutions` as above. Verify: `yarn why <pkg>`.

## Bun (bun.lock)
- Direct: `bun add <pkg>@<fixed>` (`-d` for dev). Transitive: `bun update <pkg>`; if still old, add `"overrides": { "<pkg>": "<fixed>" }` to package.json and `bun install`. Verify: `bun pm ls --all | grep <pkg>`.

## NuGet / .NET
- Direct, versions in the .csproj: `dotnet add <project>.csproj package <Pkg> --version <fixed>`.
- **Central Package Management** (`Directory.Packages.props`): change `<PackageVersion Include="<Pkg>" Version="<fixed>" />`. If a project uses `VersionOverride`, change it there instead.
- Transitive:
  - CPM: add `<PackageVersion Include="<Pkg>" Version="<fixed>" />` and set `<CentralPackageTransitivePinningEnabled>true</CentralPackageTransitivePinningEnabled>` in `Directory.Packages.props` — pins it for every project.
  - No CPM: add an explicit `<PackageReference Include="<Pkg>" Version="<fixed>" />` to the project that pulls it in (find it with `dotnet nuget why <project> <Pkg>` on SDK 8.0.4xx+, or `obj/project.assets.json`).
  - Better long-term: upgrade the parent package if a newer parent brings the fixed version.
- `packages.config` (.NET Framework): Visual Studio Package Manager Console `Update-Package <Pkg> -Version <fixed>`, or edit `packages.config` + the `<HintPath>`/`<Reference>` in the .csproj consistently. Prefer telling the user to do it in VS.
- Then: `dotnet restore`, `dotnet build`, `dotnet test`, and `dotnet list package --vulnerable --include-transitive` to confirm.
- Microsoft.AspNetCore.* / System.* packages that ship with the shared framework are fixed by the **runtime patch** (base image / hosting bundle), not by a package bump — check the advisory.

## Python
- requirements.txt: change the pinned line `pkg==<fixed>`; if generated by pip-tools, edit `requirements.in` and run `pip-compile --upgrade-package <pkg>`.
- Poetry: `poetry update <pkg>` (or `poetry add "<pkg>>=<fixed>"` if the constraint blocks it).
- uv: `uv lock --upgrade-package <pkg>`; constraint blocks it → edit `pyproject.toml`.
- Pipenv: `pipenv update <pkg>`.
- Verify: `pip-audit` if available, or re-scan.

## Go
`go get <module>@v<fixed> && go mod tidy`, then `go build ./... && go test ./...`. `govulncheck ./...` shows whether the vulnerable symbol is actually reachable. Go standard library issues (`stdlib` in the report) are fixed by upgrading the Go toolchain: `go get toolchain@go<fixed>` (updates the `toolchain` line), plus the Go version in CI (`setup-go`) and the `golang:` build image. A patch in the same line (1.22.3 → 1.22.12) is a "will apply"; a move to a newer line (1.22 → 1.24) is "needs your decision".

## Rust
`cargo update -p <crate> --precise <fixed>`; if Cargo.toml's requirement blocks it, bump the requirement. `cargo audit` to confirm.

## Ruby
`bundle update <gem> --conservative`; constraint blocks it → edit Gemfile.

## PHP
`composer update <vendor/pkg> --with-dependencies`; constraint blocks it → `composer require <vendor/pkg>:^<fixed>`. `composer audit` to confirm.

## Maven
Change the version in `pom.xml` (or a `<properties>` value). Transitive: pin in `<dependencyManagement>`. Verify with `mvn dependency:tree -Dincludes=<groupId>:<artifactId>`.

## Gradle
Direct: bump in `build.gradle(.kts)` / `libs.versions.toml`. Transitive:
```kotlin
dependencies { constraints { implementation("<group>:<artifact>:<fixed>") { because("CVE-XXXX-YYYY") } } }
```
then `gradle dependencies --write-locks` if locking is used.

## Dart / Flutter
`dart pub upgrade <pkg>` (or `flutter pub upgrade <pkg>`); constraint blocks it → edit pubspec.yaml.

## Docker base images
Edit the `FROM` tag to the latest patch in the same line (from the report's `latest`). Keep the variant suffix (`-alpine`, `-bookworm-slim`, `-jammy`). Rebuild with `docker build --pull`. Pinning by digest (`@sha256:…`) is fine; update digest and tag together.

## .NET runtime (servers / IIS)
Not fixable from the repo. Tell the user which ASP.NET Core Hosting Bundle / runtime patch to install (report `latest`) and that an app pool recycle / restart is needed.
